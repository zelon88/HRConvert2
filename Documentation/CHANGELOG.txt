-v4.0.6.
-Thanks to Github user @Hacktivistuz for filing a security advisory regarding 7-Zip that led to the containment of archive extraction & HRConvert2's own 7-Zip.
  -https://github.com/Hacktivistuz
  -https://github.com/zelon88/HRConvert2/security/advisories/GHSA-4cmg-x3g6-p322
  -GHSA-4cmg-x3g6-p322
-FIX. Archive extraction mounted the whole session conversion folder writable, so an extractor a crafted archive fooled could write & plant links beside every other file the session held. Only the extraction folder is writable now, & the folder holding the archive is read only.
-7-Zip's floor is 26.02. Every 7-Zip from 21.07 through 26.01 decodes XZ with a heap overflow, CVE-2026-14266. 25.01 & 26.01 fixed others.
-New manifest field Fallback. An apt entry declaring one has HRConvert2 build its own copy where the package manager's is missing or outside the window, into /usr/local/libexec/hrconvert2/builds. The package manager's copy is left as it is.
-An own build is asked first wherever its entry is used, & falls back to the package manager's where that one answers inside the window & it does not. One an account other than root could change is never run & reads misconfigured.
-An own build is made beside the one in service, in a folder only root can open, & is put in service only once it reports the version pinned, inside the window. One that fails leaves the one in service as it was.
-Only --setup --install-depends, --update-depends & --uninstall-depends make, refresh or take away an own build. --update-depends takes it away once the package manager catches up, & builds it again where an update moved the version pinned.
-7-Zip declares a Fallback. Where the package manager's is older than 26.02, as Ubuntu 24.04's 23.01 is, --setup --install-depends builds 7-Zip 26.06 from the source 7-Zip publishes, checked against the checksum the manifest pins. New script Documentation/Build/build-7zip.sh. DEPENDENCY_SOURCE hands it the archive on a host that cannot fetch one.
-After updating to v4.0.6 where 7-Zip is older than 26.02, run --setup --install-depends --subsystem=Archives once. Archives refuse with error 13008 until it has.
-FIX. A package manager's install was reported installed whatever version it gave. It is FAILED where that is outside the window, with the version it got.

  -Resource awareness is live.
  -Four processes, started by one command. `convertCore.php -l` (root or www-data only).
    -Derives a time-bucketed HMAC startup key from the install secret and shell_execs `convertCore.php --start-core-manager <key>`.
    -Dropping to `www-data` via `su` if you ran it as root.
    -That process validates the key, becomes Core Manager, then spawns three subordinates the same way: 
      -Request Manager, 
      -Resource Manager, 
      -or Worker Manager.
    -Each `Manager` a full `convertCore` boot that enters its `Manager` role and never returns. Into the abyss...
    -Think of `convertCore` as the mothership. Or the queen of an ant colony.
    -Every `Manager` and every `Worker` starts as a clone of `convertCore`. 
  -Uses UDS Sockets for communication.
    -Unix domain sockets in `$ConvertLoc/Sockets`, `0700`, owned by `www-data`. 
    -Every message is AES-256-GCM encrypted with a key derived from the install secret per channel, carrying a timestamp and nonce.
    -Anything outside the skew window is discarded as a replay.
  -Request flow, ONE-WAY ONLY.
    -A worker can address exactly one socket — Request Manager's.
    -Request Manager sends budget, release, or extend; anything else is refused as a request type a worker may not issue.
    -Request Manager forwards to Core Manager, which routes by type: 
    -`budget/`release`/`extend` to Resource Manager, 
    -`kill`/`reap` to Worker Manager.
    -The verdict returns back down the same open connection.
    -No worker is addressable by anything, so there is no path from one worker to another.
  -The Resource Budget.
    -Resource Manager owns the resource budget and nothing else adjusts it.
    -Every $ResourcePollInterval it reads load average and available memory, then recomputes:
      -a base of $TotalResourceBudget (or 100 units per core when zero),
      -minus a reserve percentage,
      -minus a penalty scaled to whichever of load or memory is under more pressure.
    -An idle server throttles nothing; a loaded one stops accepting before it falls over.
    -An approved request registers the worker with its cost and expected runtime and returns a budget token, which the worker hands back on completion.
  -Reaping.
    -Worker Manager sweeps every $WorkerReapInterval.
    -A tracked worker whose process has exited, or which has outrun ExpectedRuntime + $WorkerStaleGracePeriod, is killed and its budget reclaimed.
    -It is the only component permitted to end a process without negotiation.
    -Core Manager separately restarts any subordinate it finds dead.
  -Failure is open by design.
    -No component, a version mismatch, a dead listener, an unreachable socket, or a delivered request with no usable reply — all of these approve the conversion and warn.
    -The core then behaves exactly as it did before any of this existed.
    -$RequireResourceAwareness = TRUE inverts that for operators who'd rather refuse than run unaccounted.
  -Stopping.
    -The `-k` argument asks Core Manager to stop, waits for a clean unwind, then signals what remains and verifies via /proc/<pid>/stat
    -Checks process state rather than directory existence, so a zombie isn't mistaken for a survivor.
    -The `-k <id>` argument ends one worker;
    -The `--kill-all-workers` argument ends every tracked one;
    -The `--kill-every-worker` argument ends every PHP process owned by www-data, including other applications on the host.
  -State that crosses processes:
    -manager PIDs,
    -the worker registry,
    -the current budget — lives in JSON files beside the sockets.
    -That's the weakest part: last-write-wins, so a busy server could drop a registration between read and write.
      -We will eventually implement an in-memory cache for bookeeping this to remove the reliance on the filesystem.

  -This is a good approach, and it is valid to want to reduce the temporal window of data availability on the heap.
  -What our past approach lacked due consideration for is the *Footprint* of data availability.
  -By not fully understanding the *Footprint significance, we made inaccurate assumptions regarding the *Scope* of data availability.
  -PHP is a messy beast. It allocates memory simply on *Reference to a variable. So you get the same variable in memory numerous times.
  -The variable copies are not accessible easily via reference. The process for clobbering them is manual, and must be deliberate.
  -Destroying the original variable DOES NOT destroy the copies. It only destroys the original.
  -So simply the ACT of trying to destroy a variable can actually CREATE new instances of the data that variable contains in memory.
  -In order to effectively "Protect" memory, we must manage PHP memory allocations that PHP does expose to us by default.
  -We must consider the footprint we are creating in memory when we are merely *REFERENCING variables.
  -We must then make the *BEST DECISION regarding when, how, or why to REFERENCE a variable only after considering it's temporal window of exposure and the size of it's exposure footprint.
  -A good example of this is string concantenation. Every time you re-define a variable that is already defined, a new copy of that variable is stored in memory.
  -So using '.=' to update a variable "in-place" actually creates A NEW COPY of that variable in memory, and updates your ONLY reference to point to the newest copy.
  -The old copy and the new copy now exist in memory at the same time.
  -We cannot recover or clean the old copy after we PHP updates the reference to $variable. 
  -We can only ever purge whatever $variable points to in memory at that time.
  -All past copies of $variable are are located at memory addresses we do not know, and PHP does not expose to us.
  -Therefore, the best way to "protect" variables requiring concantenation is TO NOT CONCANTANATE THEM.
  -Instead, declare NEW TEMPORARY VARIABLES and destroy those when no longer needed.
  -It seems counter-intuitive that declaring MORE variables actually results in LESS memory footprint. But it's true.
  -The reason it's true is.... New variables can be recovered for destruction. Re-written ones cannot.
  -So it is CLEANER to declare MANY variables with narrow scope and destroy them than it is to redeclare the same variables over and over again.
  -For all intents and purposes, LOWER CASE FIRST LETTER VARIABLES MUST BE ONE-TIME-USE DISPOSABLE!!!!!!!!

-Hardened OpenSCAD sanitization routine.

-Fix unauthenticated arbitrary file read through OpenSCAD conversions.
  -Reported by Saudadeeee, with a working exploit against a live instance.
  -OpenSCAD reads any file the web server user can read & provides no sandbox of its own.
  -Unlike FFMPEG it cannot be given one through its arguments.
  -HRConvert2 relied on filtering the uploaded source & documented that filter as the boundary.
  -The filter read source one line at a time & held no lexer state.
  -OpenSCAD carries state across lines, so the two disagreed about some input.
  -A block comment closed part way through a line was inert to the filter & live code to OpenSCAD.
  -A statement whose name & bracket sat on different lines matched no filter pattern at all.
  -The filter did not register those cases as references at all, so no setting mitigated them.
  -The reporter noted that patching only the comment case would leave three others open. Correct.
  -The reporter recommended operating system isolation over a better filter. Also correct.
-Add verifyBwrap().
  -Launches a real minimal sandbox rather than checking that the bwrap binary exists.
  -Bubblewrap can be installed & still non functional where user namespaces are restricted.
  -A server that cannot isolate a render now refuses to render at all.
  -There is deliberately no fallback to source filtering, because source filtering does not hold.
-Rework convertSCAD() to render inside a bubblewrap namespace.
  -The session ScadTemp directory is the only path from the data tree that exists inside it.
  -Nothing else on the disk is visible, so nothing else can be read.
  -The network namespace is unshared, closing any OpenSCAD build whose import() accepts a URL.
  -The render writes inside the sandbox & the finished model is moved out afterwards.
  -Renders remain niced to the lowest priority & remain bounded by the conversion timeout.
-Replace the source filter with sanitizeSCAD(), a stateful character scanner.
  -The source is walked once, carrying line comment, block comment & string state.
  -One pass is required rather than two, because whichever delimiter appears first wins.
  -A line comment containing block comment characters does not open a block comment.
  -A block comment containing line comment characters does not open a line comment.
  -A keyword counts as a call only when the character before it is not part of an identifier.
  -That stops house_width, diffuser_height & include_lid from being reported as references.
  -A keyword counts as a call only when the next meaningful character is ( or <.
  -Whitespace & newlines are skipped, so a call split across any number of lines is found.
  -There is no line pairing & no fixed window, so an attacker cannot escape by adding newlines.
-Fix a fifth bypass reported against the new scanner before release.
  -Reported by Saudadeeee, again with confirmed reads against OpenSCAD 2021.01.
  -A comment placed between a keyword & its opening bracket slipped through.
  -surface/**/("file") is a live call because OpenSCAD treats a comment as a token separator.
  -The lookahead skipped spaces, tabs & newlines but stopped at the first character of a comment.
  -A comment is a TERMINATOR in the main scan loop & a SEPARATOR in the lookahead.
  -Those are different rules for the same construct & the earlier code applied only the first.
  -Comments are now skipped in the lookahead & again while reading the reference itself.
  -surface(/*x*/"file") is also handled, so a comment cannot hide the path from the resolver.
  -The reporter also confirmed include/**/<file> is a parser error in OpenSCAD & not exploitable.

  -The function rewrites source. It does not validate it & never did.
  -sanitizeSCAD() now names the scanner, which is the function that actually inspects.
  -Neither function is described as a security boundary anywhere in the codebase.
  -The previous header claimed the filter was the only thing standing between an upload & the filesystem.
  -That claim was false & has been replaced with a description of what the code actually does.
-Rewrite whole lines rather than editing references in place.
  -Editing in place would require reproducing where OpenSCAD considers a statement to end.
  -That is the class of problem this design exists to avoid.
  -A commented out line is coarser & is impossible to get subtly wrong.

  -A warning starts with WARNING!!! & is written regardless of Enhanced Logging Verbosity.
  -A warning is something the administrator should know is happening.
  -A warning does not necessarily mean anything needs to change.

  -A warning can never halt execution of anything.
  -Op-Act reports normal activity. WARNING!!! reports discretion advised. ERROR!!! reports numbered errors.

COMMIT - 4/14/2022
v2.8 - Major convertCore.php refactor. Complete modular redesign. Same functionality, same look, more predictable & consistent. Easier to maintain.

-v2.8.
-Refactor the core.
  -The original codebase was developed more than 4 years ago.
    -The first unpublished experiments began in 2014.
  -The "generation" of the HRConvert2 codebase until today was "Valkyrie".
    -HonestRepair server side software comes in 3 generations. 
    -The first generation is unsafe to use. It is part of the "zelon88/HRToolkitTools" repo.
      -It was called the "Genesis" engine because it was a proof-of-concept design.
      -Hence the name "Genesis".
    -The second generation is performant & safe to use but hard to maintain.
      -It is called the "Valkyrie" engine because the runtime environment is "dynamically constructed".
      -The "Valkyrie" in Norse mythology is any of a group of maidens who serves the god Odin.
      -Valkyrie's were also the "Choosers of the slain" and decided who would die on the battlefield.
      -Because the "Valkyrie" codebase is made up of one main core served by smaller cores that dynamically call dependencies.
      -Hence the name "Valkyrie" is very fitting.
    -The third and current generation is called "Diablo". It is secure, performant, & modular.
      -"Diablo" is Spanish for Devil. 
      -The coding convention was introduced in the "Zelon88/HRCloud3" alpha repo and is currently under active development. 
      -If you're a major Cloud provider you should fear Diablo.
  -Removes most core output except from log files or when logs cannot be reached.
  -Uses a more consistent logging/error catching mechanism.
  -Makes the core extremely modular and easy to work on.
  -Adding new features is easier because logging and error functions are repeatable & consistent.
  -Output is consistent.
  -Logic flow is capable of withstanding non-fatal errors.
    -Before we stopped execution for a lot more things.
    -Logic behavior is more intuitive.
  -Errors produced use incremental error numbers that can be easily adjusted or documented.
  -Log generation happens earlier during execution, meaning more logs can be captured.
    -More logs means problems are easier to identify & debug.
  -Switching to a modern design will mean more interoperability of functions between applications.
    -It becomes easier to apply simiilar patches to other products.
  -I don't have to look at my old code anymore.
    -Programmers grow. Programming styles change. 
    -I am a better programmer now than I was when I first wrote this.
    -There will probably be bugs introduced and regressions but at least I'll enjoy working on the codebase again.
    -This work needed to get done eventually anyway considering it will be needed for HRCloud3.
-Added $Verbose config entry for controlling the amount of logging performed.
  -If $Verbose is set to TRUE every significant operation will create a log entry.
  -If $Verbose is set to FALSE only errors will create a log entry.
-$VirusScan config entry now only accepts boolean values.
-Improve formatting of config.php file for readability.
-All conversions except archive conversions now receive 5 conversion attempts.
  -Previously it was only for documents and the threshold was 10 attempts.
-Reworked the way the document conversion engine is started and verified.
-Removed a lot of unused variables.
-Started using the same capitalization scheme as HRCloud3 (Diablo style).
  -Lower case first letter variables denote highly limited scope.
  -Upper case first letter variables denote very wide (almost global) scope.
  -I know that PHP takes care of memory cleanup, and I know how variable scope works in functions.
    -I also don't care. 
    -Doing the capitalization scheme and manually NULL'ing + unsetting variables helps me keep track of variables.
    -I came up with this scheme exactly because I kept seeing dead variables in my code and I wanted it to stop.
    -This forces accountability for all variables and puts visiblity on most of them.
    -So when one of them isn't used anywhere it kind of stands out.
-Refactored Javascript a tiny bit.
-Now the core will remember when you leave and come back for a short while.
-Added unique identifier for logs. 
  -Makes searching logs much easier because requests group together.
-Core now captures the stdout of it's dependencies.
  -Writes to log if $Verbose is set to TRUE.
-Changed extraction behaviour for archive conversions.
  -Archive conversions where the destination folder already exists will have the new contents ADDED to the original archive instead of replacing them.
  -You can now build archives in this fashion, admittedly it is not for the faint of heart.
-Remove sanitizeCore.php.
  -This has been replaced by the verifyGlobals() function in convertCore.php.
  -This was a suggestion made about 5 years ago on Reddit. It finally happened!
