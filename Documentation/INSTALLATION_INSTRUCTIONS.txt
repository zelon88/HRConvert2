-----THE SHORT VERSION-----

Two commands. This is the whole installation.

  sudo git clone https://github.com/zelon88/HRConvert2 /opt/HRConvert2
  sudo bash /opt/HRConvert2/Documentation/Build/hrconvert2-setup.sh

Clone it where only root can change it, as /opt is. Root will not install a tree another
account could change, so a clone in a home folder is refused.
The script installs PHP if it is missing, then hands over to convertCore.php, which does
everything else. Answer YES once, or pass -y to answer it in advance.

Then visit  http://YOUR-IP/HRProprietary/HRConvert2/convertCore.php

If that worked, read STEP 4 & STEP 5 & skip everything else. The long version exists for
an administrator who wants to know what was done to their machine, or who is installing
somewhere the automatic route cannot reach.

-----WHAT THE INSTALLER ACTUALLY DOES-----

Seven stages, in the order an installation depends on. A stage that fails stops the ones
after it, because continuing produces an installation that looks finished & is not.

  1  DEPENDENCIES
     Installs every entry in Resources/Contract/depends.php, in the order that file lists them.
     A dependency whose own requirements are missing is skipped rather than attempted.
     RAR is never installed automatically. Its licence forbids redistribution.
     Where the kernel can restrict unprivileged user namespaces, copies bubblewrap to
       /usr/local/libexec/hrconvert2/bwrap
     which only root & the web server user's group may run, & runs it as that user to prove it
     can. The AppArmor profile attached to that copy is installed too, unless an account other
     than root could put a program at that path. --setup --update-depends brings the copy up to
     date with the system's bubblewrap, & so does an update of the application. -fp never
     changes it.

  2  DATA LOCATIONS
     Creates the data location, the log directory, the backup location & the socket
     directory. Each folder the web server user writes is handed to it, & the backup is
     root's alone.

  3  PERMISSIONS & POLICIES
     Gives every managed location its role. The installation is root's & the web server
     user only reads it. See ABOUT_MANAGED_LOCATIONS.txt.
     Writes nothing for ImageMagick. Each pipeline that runs it carries its own policy into
     every conversion's sandbox, & a policy an earlier release wrote into the host is put back
     as it was.
     Writes an AppArmor profile named for the application where the kernel can restrict
     unprivileged user namespaces. It is attached to the application's own copy of bubblewrap
     & to nothing else, so every sandbox runs that copy & every other program on the host is
     restricted as before. It is not written where an account other than root could put a
     program at the copy's path. Lifts that restriction only where bubblewrap refuses a sandbox
     twice & config.php permits it, & never for an attempt cut short or to cover a copy that is
     missing or cannot be run.
     It holds for the next boot only what it changed. A restriction an earlier release lifted
     stays lifted until it is switched back on, with
       sudo sysctl kernel.apparmor_restrict_unprivileged_userns=1
     & the next -fp lets go of it wherever the copy carries a sandbox.
     Writes the PHP settings HRConvert2 needs as a drop in, never editing php.ini.
     Enables systemd lingering & cgroup delegation for per conversion resource limits.
     Installs the listener service unit, generated from this configuration, & writes the
     Environment Manager's units again wherever they are installed.

  4  CONFIGURATION
     Walks config.php section by section. With -y it keeps the shipped defaults instead.

  5  LISTENER SERVICE
     Installs & enables hrconvert2-listener, if resource awareness is enabled.

  6  PERMISSIONS, SECOND PASS
     Gives every location its role again, because stages four & five both write files.

  7  VERIFICATION
     Reports what actually works rather than what was attempted.

Then it installs. The tree it ran from is copied into Application in the data location, &
that copy's own -fp publishes the hosted location. The clone is not used again.

Every stage is idempotent. When anything looks wrong, run -fp as WHEN SOMETHING IS WRONG says.

-----STEP 1 - GET THE SOURCE-----

There are three ways to obtain HRConvert2.

  Option 1. The Docker image.
    a. Visit  'https://hub.docker.com/r/zelon88/hrconvert2'
    b. Run  'docker run -d -p 8080:80 --cap-add SYS_ADMIN zelon88/hrconvert2'
    c. SYS_ADMIN lets a container create the namespace every conversion is sandboxed in.
       Without it conversions run unprotected with a warning, or are refused where
       --Require Sandbox On Docker-- is TRUE. No process that converts or serves a user's
       file holds SYS_ADMIN, or any other capability.
    d. This guide does not otherwise apply to that option.

  Option 2. Clone the repository. This is the supported route & the rest of this guide.
    a. Run  'sudo git clone https://github.com/zelon88/HRConvert2 /opt/HRConvert2'

  Option 3. Download a release archive & extract it.
    a. Visit  'https://github.com/zelon88/HRConvert2'
    b. Extract it as root into a folder only root can change, such as /opt/HRConvert2.
    c. Everything below applies unchanged.

-----STEP 2 - KNOW WHERE IT WILL LIVE-----

Nothing is copied by hand. The installer installs HRConvert2 outside the web root, & puts in
the web root only what a browser needs.

  /DATA/HRConvert2                        The data location, root's.
    Application                           HRConvert2, root's. The web server user only reads it.
    Sessions, Cache, Logs & Sockets       The web server user's.
    Secrets                               The install secret. Its group is the web server user's.
    Engine                                Root's own logs, root's alone.
    Last-Installed-Version                The installation replaced last, root's alone.
  /var/www/html/HRProprietary/HRConvert2  The hosted location, root's.
    convertCore.php                       The loader. It hands every request to Application.
    index.html & UI                       The protection page & what a browser fetches.
    DATA                                  The files users convert, handed out only as downloads.

Each path is a default in config.php. --Data Storage Directory-- moves the first, &
--Installation Directory-- the second. The installer creates the hosted location when it is
missing. Do not place the data location inside the web root.

Every folder above both must belong to root & be writable by nobody else. Root refuses to work
beneath a folder another account can change. /var/www/html & /opt are root's on a fresh Debian
or Ubuntu. Do not hand either to the web server user.

-----------------------------------------------------------------------------------
-----STEP 3 - RUN THE INSTALLER-----

1. Run  'sudo bash /opt/HRConvert2/Documentation/Build/hrconvert2-setup.sh'
2. Answer YES when asked, or pass -y to answer in advance.
3. Read the verification table it prints at the end.

A dependency reported as absent & optional means that subsystem is unavailable & the rest
of the application works. A REQUIRED dependency reported absent means conversions using it
will refuse, & the table names which.

To install without any prompt at all, for a scripted deployment.

  sudo bash /opt/HRConvert2/Documentation/Build/hrconvert2-setup.sh -y
-----------------------------------------------------------------------------------


-----------------------------------------------------------------------------------
-----STEP 4 - CONFIGURE-----

1. Run  'cd /var/www/html/HRProprietary/HRConvert2'
2. Run  'sudo php convertCore.php --config'

Every command from here on is run from the hosted location. Its convertCore.php is the loader,
so each command reaches the installation, & --config edits the config.php it uses.

Walk each section & set what matters for this deployment. The two settings the installer
cannot decide for you are the public URL, which share links need, & the data location, if
the default does not suit this machine.

  show comment block <Variable>   Explains any setting, with its type & default.
  --config --view                 Displays everything without changing anything.
  --config --backup=/tmp/cfg.bak  Takes a copy before you start.

Nothing is written until you have walked every section, & a timestamped backup is taken
first whether or not you asked for one.
-----------------------------------------------------------------------------------


-----------------------------------------------------------------------------------
-----STEP 5 - VERIFY-----

1. Run  'php convertCore.php -v'
   Reports every dependency, every component version & every subsystem, with what is
   required beside what was found. This is the diagnostic to read first when anything
   behaves unexpectedly.

2. Run  'php convertCore.php --status'
   Reports the resource listener, the budget & the data locations.

3. Visit  'http://YOUR-IP-OR-HOSTNAME/HRProprietary/HRConvert2/convertCore.php'

4. Convert something. A conversion that fails writes the reason to the log, which is in
   the data location under Logs.

-----WHEN SOMETHING IS WRONG-----

RUN  'sudo php convertCore.php -fp'  FIRST, from the hosted location. It is idempotent, it
repairs everything the installer set up, & it verifies the result rather than assuming it worked.

RUN IT ONCE AFTER UPDATING FROM v4.0.0. Until v4.0.1 the installer & -fp handed the whole
installation to the web server user, & an installation v4.0.0 left behind keeps that
ownership until -fp gives each location its role.

RUN  'sudo php convertCore.php --setup --update-depends'  ONCE AFTER UPDATING WITH -u FROM
v4.0.4 OR EARLIER. From v4.0.5 every sandbox on a restricting kernel runs the application's own
copy of bubblewrap, & an update run by an earlier release cannot make it. An update from an
unpacked release makes it as the release is installed.

RUN  'sudo php convertCore.php --setup --install-depends --subsystem=Archives'  ONCE AFTER
UPDATING TO v4.0.6 WHERE THE HOST'S 7-ZIP IS OLDER THAN 26.02, as Ubuntu 24.04's 23.01 is. Every
7-Zip before 26.02 decodes XZ with a heap overflow, so archives refuse with error 13008 until it
has run. It builds the application's own 7-Zip from the source 7-Zip publishes, checked against
the checksum the manifest pins, & leaves the system's 7-Zip as it is. It installs a compiler where
there is none, needs a route to GitHub or 7-zip.org, & takes about a minute. --setup
--check-depends says when it is needed, & -v names the own build once it is in service.

RUN  'sudo php convertCore.php -fp'  ONCE AFTER UPDATING TO v4.0.6 WHERE FFMPEG WAS BUILT FROM
SOURCE. Until v4.0.6 that build left its whole tree, links included, in
Documentation/Build/ffmpeg-build in the installation, & root refuses to run an installation
holding a link, with error 28008. -fp takes that folder away. From v4.0.6 every source build
works in a folder of its own under /var/tmp & removes it when it ends.

RUN  'sudo php convertCore.php --config --repair'  ONCE AFTER UNPACKING THE v4.1.2 DROP IN, &
BEFORE -fp. v4.1.2 adds --User File Identification-- to config.php. -u adds it by itself.

RUN  'sudo php convertCore.php --setup --install-depends --subsystem=Identification'  AFTER
UPDATING TO v4.1.2 WHERE -v SAYS FAILED BESIDE File OR FFprobe. Identify still hashes every file
without them, & a note on each file names the tool it went without. It installs file from the
package manager. FFprobe is made by the FFMPEG build, so where FFMPEG came without it, it runs
that whole build again. PDFInfo comes in the same package as Poppler Utils.

DO NOT HAND THE INSTALLATION TO THE WEB SERVER USER WITH chown. Root runs that code. A
command run as root no longer leaves a logfile or a secret the web server user cannot use.

  Conversions refuse & the log names bubblewrap.
    The sandbox cannot create a namespace. -fp reports which of the three causes it is.
    Kernel restriction, missing AppArmor permission, or a namespace budget of zero.
    On Ubuntu 23.10 & later every sandbox runs /usr/local/libexec/hrconvert2/bwrap, which the
    hrconvert2-bwrap AppArmor profile is attached to, & -v says so beside Sandbox, Bubblewrap.
    Where -fp reports the bubblewrap copy MISSING, UNSAFE, NOT RUNNABLE, ORPHANED or BEHIND, its
    line names the command to run, which is 'sudo php convertCore.php --setup --update-depends',
    or --install-depends where bubblewrap itself has gone, & anything to correct first.

  Root refuses to run anything & names error 28008.
    Something in the installation, or a folder above it, can be changed by an account other
    than root, & the message names it. -fp corrects the installation, & takes away what an
    earlier release's build left in it. A link or a file with more than one name it does not
    know is named as -fp ends, & is removed by hand before -fp is run again. A folder above
    it, such as /var/www/html, is not this application's & is corrected by hand.
    See ABOUT_MANAGED_LOCATIONS.txt.

  Nothing appears in the log at all.
    The logfile belongs to another account. A release before v4.0.1 left the day's logfile
    root's whenever root ran the first command of the day. -fp corrects the log folder &
    leaves the files in it alone, so remove that file as root & the next entry creates it.

  A conversion works from a terminal & refuses from a browser.
    The two run as different accounts. -fp corrects ownership across both.

  The listener will not start, or does not answer.
    Run  'php convertCore.php --status'  as root, not as a standard user. A standard user
    cannot read the socket directory & is told the listener is stopped whether it is or not.

  An upload larger than a few megabytes fails.
    PHP refuses it before HRConvert2 sees it. -fp writes the drop in that permits it, &
    the web server must be restarted afterwards.

  -v reports the hosted location KEPT & names .git or .github.
    This guide copied the repository into the web root until v4.0.9. The installation uses
    neither, & the Apache configuration refuses both. Move them out of the web root.

-----STEP 6 - NETWORK ACCESS-----

HRConvert2 is only reachable on the local network until a router is configured.

1. Find the administration address of your broadband router. Try  '192.168.1.1'  or
   '10.10.1.1'  in a browser, or consult the manual.
2. Give this machine a static address, either on the router or on the machine.
3. Forward port 80, or port 443 once HTTPS is configured, to this machine.
4. For HTTPS, visit  'https://letsencrypt.org'
5. Optionally register a domain name & point an A record at the address.

DO NOT EXPOSE AN UNENCRYPTED INSTALLATION TO THE INTERNET. Files are uploaded in the
clear & share links are guessable over plain HTTP.

-----UPDATING-----

1. Run  'cd /var/www/html/HRProprietary/HRConvert2'
2. Run  'sudo php convertCore.php -u'

An update carries every setting over, except an array that differs from the new default. That
takes the new default & is named, so a deliberate change can be made again. The installation
the update replaced is kept in Last-Installed-Version, & the new release runs its own -fp.

A drop in holds only the files that changed. Unpack it into Application, keeping the config.php
in use, add any setting the release introduced with --config --repair, & run -fp there.

  sudo tar -xzf <drop in> -C /DATA/HRConvert2/Application --exclude='./Resources/config.php' --exclude='./.github'
  sudo php /DATA/HRConvert2/Application/convertCore.php --config --repair
  sudo php /DATA/HRConvert2/Application/convertCore.php -fp

--config --repair adds each setting config.php lacks, at the default the release ships, & changes
no setting already there. When nothing is missing it has nothing to do. Until it has run, every
other command refuses with error 28000, which names the settings that are missing.

Do not update by running the installer again from a new clone. It installs that clone's
config.php in place of the one in use, which is then kept only in Last-Installed-Version.

-----NOTES-----

1. HRConvert2 keeps user files completely separate & imposes no restriction on uploads.
   PHP does impose one. -fp writes the settings that permit large uploads.
2. HRConvert2 is designed to run on a dedicated server.
3. HRConvert2 does not update or patch dependencies automatically.
   Run  '--setup --update-depends'  to upgrade them, & '--setup --output-supply-chain'
   to produce an audit template of everything installed, with licences & sources.
   It also builds again an own build of the application's that an update has moved, & takes
   one away once the package manager's copy is new enough. See ABOUT_DEPENDENCIES.txt.
4. A stream conversion holds a PHP worker & an FFMPEG worker for the whole stream.
   Consider raising pm.max_children if many concurrent streams are expected.
5. rc.local is no longer used. The document conversion listener it started no longer
   exists, & the resource listener is a systemd unit the installer writes.
6. unoconv is no longer used or required. Documents are converted by LibreOffice directly,
   one sandboxed process per conversion.
7. Please respect the terms of the GPLv3 license.
8. Please reciprocate improvements back to the community with a Pull Request.
9. Report problems at  'https://github.com/zelon88/HRConvert2'
