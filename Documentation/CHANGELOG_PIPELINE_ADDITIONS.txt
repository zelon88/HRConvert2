CHANGELOG.txt ADDITIONS FOR HRConvert2 v3.8.5.
Append this block to CHANGELOG.txt. Convention 11.
Conversion pipelines became detachable, versioned components.
----------------------------------------------------------------------------------------------------------------------------------------------------------------


--SUMMARY--

  convertCore.php converts nothing on its own any more. Thirteen conversion families now
  live in versioned component folders under Resources/Pipelines, each pinned EXACTLY by a
  new Pipeline Manager component which is itself pinned EXACTLY by the core.
  convertCore.php went from 9434 lines to 7455.

  Core version v3.8.4 -> v3.8.5. $RequiredPipelineManagerVersion v3.8.1 -> v3.8.5.
  $RequiredConfigVersion, $RequiredGuiVersion, $RequiredLanguageVersion,
  $RequiredCoreManagerVersion, $RequiredSetupCoreVersion, $RequiredDependencyCoreVersion,
  $RequiredDependsVersion & $RequiredSecretVersion are UNCHANGED. Those components were not
  touched & bumping their pins would refuse installations that are working correctly.


--NEW FILES--

  Resources/Pipelines/pipelineManager.php                          v3.8.5
    The Pipeline Manager component. Owns the pin list for every pipeline & shared module it
    accepts, reads their declarations without executing them, ranks implementations, and
    dispatches. Twelve functions. getAcceptedPipelines, getAcceptedSharedModules,
    loadSharedModule, verifyPipelineComponent, validatePipelineDeclarations,
    enumeratePipelines, pipelineClaimsConversion, describePipelineCapabilities,
    buildPipelineFormatArrays, resolvePipelineCandidates, familyHasPipeline,
    loadPipelineCore, runOcrOperation & runConversion.
    Reserves error block 32000 through 32019.

  Resources/Pipelines/<Family>/pipelineConfig.php                  v3.8.5
  Resources/Pipelines/<Family>/pipelineCore.php                    v3.8.5
    Thirteen pipelines. Archive, Audio, Document, Drawing, Ebook, Image, Model, OCR, Scad,
    Stream, Subtitle, SVG & Video. Each folder carries its declarations & its converter, is
    version pinned as a whole by pipelineConfig.php, & is loaded only when an operation is
    about to be dispatched to it. A request converting an image never parses a line of the
    Document pipeline.

  Resources/Pipelines/Shared/libreOffice.php                       v3.8.5
    The first shared module. A shared module is not a pipeline, converts nothing, and is
    never dispatched to. It exists for code two or more pipelines both need & neither can
    own. convertWithLibreOffice() has callers in the Document pipeline and the OCR
    pipeline. Holds sanitizeDocumentLinks, neutralizeDocumentReferences,
    verifyDocumentConversionEngine & convertWithLibreOffice, all moved unchanged.
    Carries error block 2000 through 2004.

  Documentation/ABOUT_PIPELINE_COMPONENTS.txt
    The contracts every pipeline obeys, the folder layout, the version pinning rules, what
    belongs to the core versus a pipeline, how to write a detached worker pipeline, and the
    staging this migration followed.

  Resources/Pipelines/index.html & one in every pipeline & shared folder.
    Document root protection. Copied from an existing one, never written fresh.


--convertCore.php, THE SIX VALUE PIPELINE CONTRACT--

  Every converter returns six values in a fixed order. Success, errors, output path, output
  extension, output filename, worker PID.

  Ten converters gained $OutputFilename & $WorkerPID and returned six values instead of
  four. convertArchives gained $WorkerPID only, having already declared $UserFilename as
  its fifth value.

  convertStreams was reshaped rather than extended. It no longer returns $WaitForStream and
  its local copy of that variable was removed. It returns the output path, an $Extension
  derived from that path, an $OutputFilename & its process ID. $newPathname came out of its
  purgeSensitiveMemory call, because a returned value is never purged.


--convertCore.php, DISPATCH--

  convert() asks familyHasPipeline() with the family, the input extension AND the output
  extension before dispatching. ACTIVE IS NOT THE SAME QUESTION AS SERVES. An earlier
  revision asked only whether the manager had loaded, which handed it every conversion and
  lost the ones no pipeline claimed.

  convert() derives $WaitForStream, $StreamPID & $StreamOutputPath from a non zero
  $WorkerPID, so any pipeline whose dependency outlives the request is supervised by the
  code that previously supervised only FFMPEG streams.

  convert() guards an empty filename slot before returning, because an undefined value in
  an AJAX reply is a PHP warning the interface reads as a line of the response.

  The built in dispatcher and $builtInDispatcherFamilies are REMOVED. They existed for the
  whole migration and each family left individually as its body moved out, so a mistake
  never cost more than one family. An unserved family raises 32005.

  Thirteen converter functions were removed from this file entirely, with their helpers,
  and now live in their pipeline folders unchanged, error numbers included.

  ocrFiles() is now the OCR operation pipeline. The OCR request handler calls
  runOcrOperation() and prints the filename list it returns.


--convertCore.php, COMPONENT LOADING & GLOBALS--

  verifyInstallation() pins $RequiredPipelineManagerVersion and carries it on its globals
  line.

  The main logic verifies the component and enumerates pipelines directly after
  verifyGlobals(), so refusal warnings have a logfile to land in. No pipeline code executes
  during enumeration. Only declarations are read.

  verifyGlobals() now states $PipelineManagerActive, $PipelinesAreEnumerated, $Pipelines &
  $PipelineCount, and declares all four on its globals line. A CLI path that never reaches
  the Pipeline Manager finds them defined instead of raising a notice on first read.

  The stream initializers became a Detached worker variables section with a comment
  describing what the path is now for.

  showVersionInfo() reports the Pipeline Manager version and the verified pipeline count. A
  manager that loaded but verified nothing is reported differently from one that never
  loaded, because the version line alone cannot tell those apart.

  A missing, unreadable or version mismatched Pipeline Manager is a WARNING and never an
  error. The manager also stands itself down when it verifies nothing, because a dispatcher
  with nothing behind it is worse than no dispatcher.


--WHAT STAYED IN THE CORE, AND THE RULES THAT DECIDED IT--

  THE MECHANICAL RULE. A helper moves with its pipeline when convertCore.php has no other
  caller for it. showVersionInfo() runs whether or not a pipeline is installed, so anything
  it calls is core owned by definition. That settled every verify*Version() function.

  THE POLICY EXCEPTION. THE CORE OWNS THE NETWORK. A PIPELINE OWNS ITS FORMAT.
  Eight functions have no caller outside the Stream pipeline and stayed anyway.
  isPubliclyRoutableIP, dnsLookup, gatherRemoteHostInfo, resolveRemoteURI,
  inspectContentForIPs, inspectContentForDomains, downloadRemoteFileForInspection &
  waitForStream. A pipeline must never own SSRF protection. Somebody writing their own
  fetch forgets to pin the resolved IP, follows a redirect, or does not bound the read, and
  the result is a server that can be aimed at an internal network. Network egress is core
  owned by policy rather than by caller count, exactly as verifyFile() and virusScan() are.

  RENAMED so the next pipeline can find them. None of them knows anything about playlists.
    gatherRemoteStreamHostInfo  ->  gatherRemoteHostInfo
    resolveStreamURI            ->  resolveRemoteURI
    inspectStreamIP             ->  inspectContentForIPs
    inspectStreamDomain         ->  inspectContentForDomains
    downloadStreamFile          ->  downloadRemoteFileForInspection
  Their parameters and returns were generalized too. $streamFileContents became
  $fileContents. $StreamContainsLAN, $StreamContainsIP & $StreamContainsDomain became
  $ContentContainsLAN, $ContentContainsIP & $ContentContainsDomain.

  THE SANDBOX PROFILES STAYED. verifyOpenScadPolicy, openScadApparmorContents,
  verifyImageMagickPolicy, resolveImageMagickConfigDir & imageMagickPolicyContents are
  written and checked by fixManagedPermissions() and validateOperatingEnvironment() during
  installation, whether or not the pipeline is installed. A sandbox profile is part of the
  machine, not part of a converter.

  MOVED WITH THEIR PIPELINES, having no other caller.
    Scad     sanitizeSCAD, resolveSCADInclude, rectifySCAD, sanitizeAllSCADUploads
    Archive  verifyIsoBootloaders, generateBootableIsoCommand
    Stream   streamFileWalker, inspectTSFile, classifyStreamContent, inspectStreamFile


--NEW MECHANISMS--

  SHARED MODULES. getAcceptedSharedModules() pins each module EXACTLY as an allowlist.
  loadSharedModule() reads the version without executing, refuses one reporting none, and
  loads with require_once. Declared modules load BEFORE the converter that declared them.
  $PipelineSharedModules declares which a pipeline needs.

  PIPELINE KINDS. $PipelineKind distinguishes a conversion pipeline from an operation
  pipeline. Undeclared means conversion. resolvePipelineCandidates() skips anything that is
  not a conversion pipeline, so convert() can never reach OCR with the wrong signature.

  OPERATION PIPELINES. OCR takes a selection of files, routes each one differently, and
  returns three values rather than six. runOcrOperation() dispatches it. Fallback across
  implementations is deliberately NOT attempted, because a half completed OCR batch has
  already written files the user can see and already consumed budget.

  DETACHED WORKER PIPELINES. A non zero sixth return value means the core supervises a
  process after the connection to the user has closed. Streaming is the reference
  implementation and is no longer the only permitted one. The four pieces of that
  passthrough are documented in ABOUT_PIPELINE_COMPONENTS.txt so that nobody builds their
  own and gets the reaping half wrong.

  RANKED FALLBACK. Two folders may declare the same family. Enumeration merges them and
  dispatch tries them in $PipelinePriority order, unlinking the output path between
  attempts so a second candidate cannot inherit a partial file from the first and report a
  success that never happened.


--BUGS FOUND & FIXED ALONG THE WAY--

  streamFileWalker() logged its walk result TWICE. An identical block sat above the loop
  where every counter was still zero and $InspectionFailed was still FALSE, so every
  refused walk logged ALLOWED with all zeroes and then DENIED with the real numbers. An
  operator reading that saw a walk succeed and then fail. Only the second line was ever
  real. The premature copy is removed. The surviving one now warns on a denial rather than
  logging under $Verbose, so a refusal is visible without verbose logging on. This bug
  predates this work.

  The OCR pipeline PRINTED into the AJAX response, violating contract 6. Safe while it
  lived in convertCore.php, not safe from a component whose output shares a stream with a
  PHP warning. It collects the filenames and returns them, and the core prints them. The
  reply the interface receives is byte for byte what it was.

  32003 restated refusals that a pipeline had already explained. A denied stream produced a
  correct, well explained refusal followed by a louder line claiming every pipeline failed,
  which sends an operator looking for a fault that is not there. 32003 now fires only when
  a pipeline fails and reports nothing at all.


--DECISIONS THAT CHANGED DURING THE WORK--

  ERROR BLOCK. 31000 was proposed and abandoned. The shipping core already calls 31008
  through 31016 from the Core Manager command line paths. 32000 through 32019 is used.

  NO EXISTING ERROR NUMBER CHANGED VALUE. Thirteen converters moved files and carried their
  documented numbers with them unchanged.

  CAPABILITY DECLARATIONS DO NOT NARROW config.php. pipelineClaimsConversion() reads
  $SupportedFormatDetectionType with a local hardcoded-only fallback that configuration
  cannot overwrite. Under that mode, which is what every installation runs today, the
  declared Input and Output lists are informational and only $PipelineExclude is enforced.
  convertFiles() has already tested the pair against the administrator's format arrays
  before anything reaches the manager, so testing it again against a hand written list
  would let an omission quietly delete a working conversion.

  NAMES WERE NOT CHANGED WHERE AN ADMINISTRATOR OWNS THEM. $StreamWatchTimeout,
  $AllowStreamOverHTTP, $StreamConnectionTimeout, $MaxStreamInspectionFileSize and
  $StreamTemp all now govern any pipeline rather than only streaming, and all keep their
  names. An administrator's config.php names them and a rename would silently reset those
  settings on every installation in the world. The comments were rewritten instead.


--STILL OWED--

  Documentation/CREATING_CONVERSION_PIPELINES.txt still states that every pipeline lives in
  convertCore.php and does not describe contracts 4, 5 or 6, operation pipelines, shared
  modules, or detached workers. It needs rewriting against ABOUT_PIPELINE_COMPONENTS.txt.

  config.php does not carry $SupportedFormatDetectionType or $WarnOnCapabilityMismatch yet.
  Both are read defensively and default safely without them.

  The capability lists in all thirteen pipelines have NOT been diffed against config.php.
  They do not need to be while detection is hardcoded-only. They must be before capability
  detection is enabled.

  Interface enumeration from the live capability set, capability detection and its cache, a
  second implementation of one family to exercise ranked fallback for real, and pipeline
  chaining are all unimplemented. The machinery they need is in place.
